## Phát hiện từ spike (2026-10-19, CPU i5-9300H)

- **RapidOCR 3.10** (PP-OCRv6 det small, ONNX) có sẵn trong package: detect 1 trang 300 DPI ≈ 2.5s. Gọi `RapidOCR()(img, use_det=..., use_cls=..., use_rec=...)` — **luôn truyền đủ 3 cờ**, vì cờ của lần gọi trước bị giữ lại.
- **VietOCR `vgg_seq2seq`** ≈ 0.16s/dòng (batch), đọc tốt tiếng Việt in máy; `vgg_transformer` chậm hơn ~4× → mặc định `vgg_seq2seq`. `Cfg.load_config_from_name` tải config từ Internet mỗi lần, và backbone VGG mặc định tải trọng số ImageNet → phải lưu config/weights local và đặt `cnn.pretrained = False`.
- **Xác suất của VietOCR dồn quanh 0.85–0.91** cả với dòng đúng; dòng sai dấu vẫn ~0.78. Ngưỡng 0.90/0.80 trong thiết kế **phải hiệu chỉnh lại bằng eval** (M3), nếu không gần như mọi vùng sẽ bị gửi VLM.
- **Heron layout** (`docling-project/docling-layout-heron`, RT-DETRv2) chạy trực tiếp qua `transformers` (`AutoModelForObjectDetection`), ≈ 2s/trang; nhận ra `checkbox_selected/unselected`, `form`, `key_value_region`, `picture` (sơ đồ), `table`. Kết quả thô có nhiều box trùng (cùng vùng, khác nhãn) → cần NMS + luật container.
- API layout nội bộ của Docling thay đổi theo phiên bản (`docling_ibm_models.layoutmodel` đã bị bỏ) → **không phụ thuộc API nội bộ Docling**, gọi model qua `transformers`.

## Trạng thái triển khai (2026-10-19)

Đã code M1–M7 theo TDD: 243 test backend nhanh, 5 test backend chậm (model thật), 20 test frontend. Kết quả trên file mẫu: [docs/output/README.md](../output/README.md).

### Khác so với thiết kế (và lý do)

| Thiết kế | Thực tế | Lý do |
|---|---|---|
| TableFormer cho cấu trúc bảng | **Dò lưới đường kẻ bằng OpenCV + OCR từng ô**; bảng không đường kẻ dùng gom cụm dòng | Hồ sơ mẫu đều là bảng có kẻ. Cách này chạy được trên CPU, xác định được, dựng đúng ô gộp; API TableFormer nội bộ của Docling không ổn định |
| Docling native cho DOCX/PPTX/HTML, calamine cho XLSX | python-docx / python-pptx / BeautifulSoup / openpyxl | Kiểm soát được ô gộp và font VNI/TCVN3 theo từng run; `docling-slim` thiếu các backend Office |
| Kiểm tra số học: công thức BCTC + tổng | Thêm: số sai định dạng trong cột số; phần trăm so theo giá trị tuyệt đối | Báo động giả trên dòng thuế `(336)`; cần chỉ ra đúng ô gây lỗi |
| Tách mực theo ngưỡng màu | Thêm dò dấu tròn bằng Hough (tách dấu khỏi chữ viết tay chồng lên), dấu chữ nhật nghiêng, khử vệt sọc scan, bút dạ quang thành nền | Các loại nhiễu này đều có trong file mẫu |
| Chạy lại từ trang chưa xong khi khởi động lại | Chạy lại cả tài liệu đang dở | Đơn giản hơn; trang đã xong vẫn được lưu `pages/<n>.json` để xem ngay |
| Ngưỡng VLM 0.90 | 0.85 (chỉnh trong UI) | Độ tự tin của VietOCR dồn quanh 0.85–0.91 |

### Việc còn lại
- Gán nhãn đúng cho 13 trang trên UI, rồi đo CER/TEDS và hiệu chỉnh ngưỡng.
- Cấu hình LLM Gateway MB và chạy lại để tầng VLM xử lý dấu tròn, chữ viết tay và sơ đồ (Mermaid).
- `idp synth` (bộ sinh dữ liệu tổng hợp) và chế độ so sánh engine: chưa làm.
